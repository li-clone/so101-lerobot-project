# 阶段 0：从深度学习到机器人策略

## 0. 本阶段目标

完成这一阶段后，你应该能：

- 区分 `state`、`observation`、`action`、`policy`。
- 解释 `demonstration`、`trajectory`、`episode`、`rollout`。
- 画出机器人策略的训练流程和真机推理流程。
- 理解机器人学习为什么不只是普通图像监督学习。
- 解释为什么 training loss 降低，不代表真机成功率一定提高。
- 区分开环执行、策略闭环和电机底层闭环。
- 理解 checkpoint 在训练恢复和真机部署中的不同作用。

本阶段暂不深入 ACT 的 Transformer、CVAE 和 action chunk 内部结构。

## 1. 从 CS231n 到机器人学习

在普通图像分类中，我们学习：

```text
图片 x
  ↓
神经网络 fθ
  ↓
类别预测 ŷ
  ↓
与标签 y 比较
  ↓
loss
```

预测完成以后，模型不会改变输入图片。

机器人学习则不同：

```text
当前观察 oₜ
  ↓
策略 πθ
  ↓
动作 aₜ
  ↓
机器人和环境发生变化
  ↓
产生下一时刻观察 oₜ₊₁
```

也就是：

```text
oₜ → aₜ → oₜ₊₁
```

策略的预测会改变它未来将看到的数据。

这是从普通深度学习进入机器人学习时，最重要的思维变化：

> 图像分类是“对已有数据作预测”，机器人策略是“通过预测参与生成未来数据”。

因此，机器人上的一个小错误可能改变下一时刻的观察，再影响下一次动作，最终形成连续误差。

---

## 2. 机器人与环境的基本交互循环

可以用下面的抽象描述机器人系统：

$$
s_{t+1}=f(s_t,a_t,\epsilon_t)
$$

$$
o_t=g(s_t)
$$

$$
a_t=\pi_\theta(o_t)
$$

各符号含义如下：

- $s_t$：环境在时刻 $t$ 的真实状态。
- $o_t$：机器人能够获得的观察。
- $a_t$：策略给出的动作命令。
- $\pi_\theta$：参数为 $\theta$ 的策略模型。
- $f$：机器人和环境的物理变化规律。
- $g$：从真实世界状态产生传感器观察的过程。
- $\epsilon_t$：摩擦、噪声、延迟等不确定因素。

对应你的 SO-101：

```text
真实场景状态 sₜ
├── 机械臂真实关节位置
├── 物体真实位置和姿态
├── 夹爪与物体接触状态
├── 摩擦力
└── 相机、机械臂、桌面的空间关系

机器人观察 oₜ
├── 正面相机图像
├── 侧面相机图像
└── 机械臂关节状态

ACT 策略 πθ
└── 根据观察预测动作

动作 aₜ
└── 各关节或电机的目标命令
```

## 3. State 和 Observation 的区别

### 3.1 State：世界实际上是什么样

State 指能够完整描述当前系统的信息。

例如：

- 所有关节的真实角度和速度。
- 物体的精确三维位置。
- 物体是否已经被夹紧。
- 接触力和摩擦状态。
- 相机精确外参。
- 电机真实温度和负载。

真实世界中，我们通常拿不到完整 state。

### 3.2 Observation：机器人实际看到了什么

Observation 是传感器提供给策略的信息，例如：

```python
observation = {
    "observation.images.front": front_image,
    "observation.images.side": side_image,
    "observation.state": joint_positions,
}
```

这里需要注意一个容易混淆的命名：

> LeRobot 中的 `observation.state` 是一个字段名称，通常表示机器人本体状态，但它不一定是理论上的完整环境 state。

例如，`observation.state` 可能包含关节位置，却没有物体精确位置、接触力和相机遮挡信息。

因此：

$$
o_t \neq s_t
$$

通常 observation 只是 state 的不完整、带噪声表示。

### 3.3 为什么这个区别重要

假设杯子被机械臂挡住：

- 真实 state 中，杯子仍然存在于某个位置。
- 当前相机 observation 中，杯子可能完全不可见。
- 如果策略只看当前一帧，它可能无法判断杯子在哪里。
- 如果策略能利用历史观察，就可能记住杯子先前的位置。

这也是后面学习 observation history、时序模型和动作序列的基础。

## 4. Action 不是“机器人实际运动”

Action 更准确地说，是策略希望机器人执行的命令。

例如：

```text
策略输出：
shoulder_pan.pos = 12.4
elbow_flex.pos   = -31.2
gripper.pos      = 67.0
```

但机器人最终的真实运动还会受到这些因素影响：

- 动作限幅。
- 速度限制。
- 电机底层控制器。
- 机械结构误差。
- 负载、摩擦和碰撞。
- 通信延迟。
- 标定误差。

因此要区分三个概念：

```text
策略预测的动作
      ↓
经过反归一化、安全限制等处理
      ↓
实际发送给电机的动作
      ↓
机器人产生的真实运动
```

这三者不一定完全相同。

LeRobot 的机器人接口正是围绕这个循环组织的：

```python
observation = robot.get_observation()
action = policy.select_action(observation)
sent_action = robot.send_action(action)
```

其中 `send_action()` 返回的可能是经过安全限制后实际发送的命令。

参考：[LeRobot Robot 接口](https://huggingface.co/docs/lerobot/main/api/robots)

## 5. Policy 到底是什么

Policy 是从观察到动作的决策规则：

$$
a_t=\pi_\theta(o_t)
$$

最简单的神经网络 Behavior Cloning 可以写成：

```python
predicted_action = policy(observation)
```

更一般地，策略可能还使用：

- 历史观察。
- 历史动作。
- 语言任务指令。
- 随机 latent 或噪声。
- 内部缓存状态。

于是可以写成：

$$
a_t \sim \pi_\theta(a_t\mid o_{\leq t},\text{task})
$$

这里的“$\sim$”表示策略可能描述一个动作分布，而不只是输出唯一动作。

对于 ACT，输出甚至不是单个动作，而是一段未来动作：

$$
\hat A_t=
[\hat a_t,\hat a_{t+1},\dots,\hat a_{t+H-1}]
$$

但执行系统最终仍然要在当前控制时刻选择一个动作发送给机器人。

在当前 LeRobot 接口中：

- `forward(batch)`：主要用于训练并返回 loss。
- `predict_action_chunk(batch)`：预测完整动作块。
- `select_action(batch)`：返回当前要执行的一个动作。

这是后面阅读 ACT 源码时非常重要的接口分工。

参考：[LeRobot Policy 接口说明](https://huggingface.co/docs/lerobot/main/en/bring_your_own_policies)

## 6. Demonstration、Trajectory、Episode 和 Rollout

### 6.1 Demonstration

人类专家提供的一次示范数据。

你的项目中通常来自 leader arm 控制 follower arm：

```text
人类控制 leader
    ↓
follower 执行动作
    ↓
同时记录图像、关节状态、动作
```

### 6.2 Trajectory

一个随时间排列的数据序列：

$$
\tau=
(o_0,a_0,o_1,a_1,\dots,o_T,a_T)
$$

Trajectory 强调的是“这条时序轨迹”。

### 6.3 Episode

一次有明确开始和结束的任务尝试：

```text
reset 场景
→ 开始抓取
→ 执行任务
→ 成功/失败/超时
→ episode 结束
```

一个 episode 通常对应一条 trajectory，但两者强调角度不同：

- trajectory 强调时序数据。
- episode 强调一次完整交互单元。

### 6.4 Rollout

让某个 policy 在环境中实际运行，产生一条轨迹。

```text
policy + environment → rollout
```

需要区分：

- 人类专家运行产生 demonstration。
- ACT 自主运行产生 policy rollout。
- rollout 可能成功，也可能失败。
- rollout 也可以被记录并用于后续分析或数据补充。

## 7. 训练流程

你的 ACT 训练在抽象层面仍然属于深度学习训练：

```text
示教 episodes
     ↓
Dataset
     ↓
采样训练样本
     ↓
DataLoader 组成 batch
     ↓
图像/状态/动作预处理
     ↓
policy.forward(batch)
     ↓
loss
     ↓
loss.backward()
     ↓
optimizer.step()
     ↓
保存 checkpoint
```

用伪代码表示：

```python
for batch in dataloader:
    loss, loss_info = policy.forward(batch)

    optimizer.zero_grad()
    loss.backward()
    optimizer.step()
```

这与 CS231n 完全相通：

| CS231n/视觉任务 | 机器人模仿学习 |
|---|---|
| image | camera observation |
| label | expert action |
| classifier | policy |
| predicted class | predicted action |
| classification loss | action imitation loss |
| accuracy | 离线动作误差或任务成功率 |

但是存在一个关键区别：

> 训练 batch 来自人类示范；部署时 observation 来自策略自己先前动作造成的状态。

这正是后面 Behavior Cloning 中 distribution shift 的来源。

## 8. 真机推理流程

部署时不再有 expert action，也不计算训练 loss：

```text
连接机器人
   ↓
episode reset
   ↓
读取当前 observation
   ↓
预处理 observation
   ↓
policy.select_action()
   ↓
动作反归一化/安全处理
   ↓
robot.send_action()
   ↓
等待下一个控制时刻
   ↓
重新读取 observation
```

伪代码：

```python
policy.eval()
policy.reset()

while not episode_finished:
    observation = robot.get_observation()

    model_input = preprocess(observation)

    with torch.no_grad():
        action = policy.select_action(model_input)

    robot_action = postprocess(action)
    robot.send_action(robot_action)
```

当前 LeRobot 使用 `lerobot-rollout` 加载 policy 并在真机上运行自主 rollout。

参考：[LeRobot 真机模仿学习流程](https://huggingface.co/docs/lerobot/il_robots)

这里有三个容易忽略的细节。

### 8.1 `policy.eval()`

关闭或改变 Dropout、BatchNorm 等模块的训练行为。

### 8.2 `torch.no_grad()`

推理时不保存反向传播需要的计算图，降低显存和计算开销。

### 8.3 `policy.reset()`

新 episode 开始时，清除策略内部缓存，例如尚未执行的动作队列。

## 9. Checkpoint 是什么

“Checkpoint”在不同语境下可能指两类东西。

### 9.1 用于继续训练的 checkpoint

通常包括：

- 模型参数。
- optimizer 状态。
- learning-rate scheduler 状态。
- 当前训练 step。
- 配置。
- 有时还包括随机数状态等信息。

作用是：

```text
训练到 step 30000
→ 中断
→ 载入 checkpoint
→ 从 step 30000 附近继续训练
```

### 9.2 用于部署的模型产物

至少需要：

- 模型权重。
- 模型配置。
- 输入输出特征定义。
- 与训练一致的预处理/后处理信息。
- 归一化统计量或对应 processor。

作用是：

```text
加载训练好的 policy
→ 输入 observation
→ 输出 action
```

因此，“有一个 `.safetensors` 文件”不一定意味着完整具备可部署条件。模型必须知道：

- 输入有哪些相机。
- 关节状态维度是多少。
- action 维度是多少。
- 图像如何缩放。
- state/action 如何归一化。
- ACT 的 chunk 参数是什么。

当前 LeRobot 的 policy 继承 `PreTrainedPolicy`，通过配置和权重恢复模型，并区分训练用 `forward()` 与推理用 `select_action()`。

参考：[LeRobot PreTrainedPolicy](https://huggingface.co/docs/lerobot/main/en/api/policies)

## 10. 为什么 loss 低不等于真机成功率高

这是阶段 0 最重要的问题之一。

训练优化的是类似下面的平均动作误差：

$$
\mathcal L(\theta)
=
\frac{1}{N}
\sum_{i=1}^{N}
\ell\bigl(\pi_\theta(o_i),a_i^*\bigr)
$$

但真实任务关心的是：

$$
\text{Success}=
\begin{cases}
1,&\text{任务完成}\\
0,&\text{任务失败}
\end{cases}
$$

两者不是同一个目标。

### 10.1 不同时间点的重要性不同

机械臂在空中移动时出现少量误差，可能没有影响。

夹爪接触物体的一瞬间出现同样大小的误差，可能导致整个任务失败。

但普通平均 loss 未必知道哪个时刻更关键。

### 10.2 误差会连续累积

训练数据中的 observation 来自人类正确操作。

部署时，一次轻微偏差可能导致机械臂来到训练集中很少出现的位置：

```text
第一次预测略偏
→ 下一帧视觉和关节状态发生变化
→ 模型进入不熟悉的 observation
→ 第二次预测偏差更大
→ 最终失败
```

### 10.3 动作可能存在多种正确答案

从杯子左边绕过去和从右边绕过去都可能成功。

如果数据中两种动作混在一起，普通回归模型可能学习到两者平均：

```text
左绕动作 + 右绕动作
        ↓
      平均动作
        ↓
可能直接撞向中间障碍
```

### 10.4 训练集不覆盖部署变化

例如：

- 物体位置变化更大。
- 光照变化。
- 相机轻微移动。
- reset 状态不同。
- 机械臂发生遮挡。
- 夹取失败后进入恢复状态。

### 10.5 训练和部署的数据处理不一致

例如：

- 相机顺序不同。
- 图像 resize 不同。
- 归一化统计量不一致。
- action 单位或尺度错误。
- 关节顺序发生变化。

所以评估策略时需要同时看：

```text
训练 loss
+
验证集 loss
+
真机 rollout 成功率
+
失败类型
+
动作轨迹表现
```

## 11. 开环与闭环

### 11.1 开环执行

先产生动作序列，然后不再观察环境：

```text
观察一次
  ↓
生成全部动作
  ↓
完整执行
  ↓
过程中不根据新观察修正
```

如果物体移动、动作出现偏差，系统无法及时调整。

### 11.2 策略闭环

每执行一段动作后重新观察：

```text
观察 oₜ
→ 预测动作
→ 执行动作
→ 获得 oₜ₊₁
→ 再预测
```

新的 observation 会反馈给 policy，因此这是闭环。

### 11.3 ACT 输出动作块是否意味着开环

不一定。

ACT 可以预测未来一段动作：

```text
[aₜ, aₜ₊₁, ..., aₜ₊H]
```

系统可以只执行其中前几个动作，然后重新观察和预测。

因此更准确的说法是：

> ACT 在一个动作块内部可能短时开环，但整个 rollout 可以在动作块粒度上保持闭环。

具体执行多少动作、多久重新推理，将在 ACT 阶段详细学习。

### 11.4 机器人中存在多层闭环

你的系统至少可以有两层反馈：

```text
学习策略闭环
相机/关节观察 → ACT → 目标动作
                     ↓
电机控制闭环
编码器反馈 → 电机控制器 → 电机输出
```

所以“policy 是闭环的”不等于“policy 自己实现了所有底层控制”。

ACT 通常负责生成目标动作；电机控制器负责让关节跟踪目标。

## 12. 阶段 0 的完整心智模型

```text
             人类示教
                ↓
      ┌──────────────────┐
      │ Demonstration    │
      │ Episodes         │
      │ (oₜ, aₜ*)        │
      └────────┬─────────┘
               ↓
            Dataset
               ↓
          DataLoader/Batch
               ↓
         Policy.forward()
               ↓
             Loss
               ↓
      Backward + Optimizer
               ↓
           Checkpoint
               ↓
      ─────部署分界线─────
               ↓
        加载 Policy/Config
               ↓
┌──────────闭环 Rollout───────────┐
│                                 │
│  Robot/Environment              │
│       ↓                         │
│  Observation oₜ                 │
│       ↓                         │
│  Policy.select_action()         │
│       ↓                         │
│  Action aₜ                      │
│       ↓                         │
│  Robot.send_action()            │
│       ↓                         │
│  环境变化，产生 oₜ₊₁ ──────────┘
│
└→ success / failure / timeout
```
